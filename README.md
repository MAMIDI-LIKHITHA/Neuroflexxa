# Neuroflexxa

**Simulation-first FPGA biosignal-processing prototype.**

Neuroflexxa is an early engineering prototype exploring a deterministic streaming pipeline for biosignal samples. The initial repository baseline provides a small, parameterized RTL core and a reproducible simulation test. It is not a medical device and is not intended for diagnosis, treatment, seizure prediction, clinical decisions, or real-world prosthetic control.

## Current implementation

The initial baseline is deliberately narrow:

- Ready/valid streaming input and output.
- A three-tap low-pass FIR stage with coefficients [1, 2, 1] / 4.
- Absolute-amplitude threshold event tagging.
- A sample counter used as a relative timestamp.
- A one-entry output register that holds its payload under backpressure.
- A self-checking testbench and Icarus Verilog simulation target.

This is a **simulation baseline**, not evidence of FPGA timing, resource utilization, power, sensor-to-action latency, or clinical performance.

## Quick start

Requirements: Icarus Verilog (`iverilog`) and `vvp`, plus GNU Make.

```sh
make test
```

Or run directly:

```sh
mkdir -p build
iverilog -g2012 -Wall -s tb_neuroflexxa_core -o build/neuroflexxa_tb rtl/neuroflexxa_core.v tests/tb_neuroflexxa_core.v
vvp build/neuroflexxa_tb
```

A successful run prints `PASS: Neuroflexxa core smoke test`.

## Initial interface assumptions

The first baseline is workload-agnostic and uses signed fixed-width sample values. No EEG/EMG/ECG workload, sampling rate, ADC format, FPGA part, board, or external output interface has yet been selected. The default parameters are simulation conveniences, not validated biosignal settings. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/INTERFACE_SPEC.md](docs/INTERFACE_SPEC.md).

## Evidence policy

Only results generated by reproducible commands and stored with their tool versions and configuration may be described as verified. Do not infer hardware performance from RTL simulation. Keep simulated pipeline latency separate from sensor-to-action latency.
